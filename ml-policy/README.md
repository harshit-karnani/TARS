# TARS ML-Based Adaptive Risk Scoring (Shadow Mode)

This directory contains the machine learning components for TARS's adaptive risk scoring capability, running strictly in **observational shadow mode**.

---

## 1. Overview & Architecture

The ML risk classifier acts as an auxiliary security intelligence feature. It intercepts tool call features in real time, generates risk category predictions (`LOW`, `MEDIUM`, `HIGH`) with class probabilities, and attaches these predictions to TARS audit events.

### Critical Security Boundaries
- **Shadow Mode Only**: The ML model never replaces, overrides, or alters the deterministic policy decisions (`ALLOW`, `BLOCK`, `REQUIRE_APPROVAL`).
- **Fail-Safe Isolation**: If the Python service is offline, slow, or encounters errors, the deterministic policy engine continues without disruption.
- **Privacy & Secret Redaction**: Only 10 extracted behavioral features (lengths, flags, category tags) are sent to the model. Raw tool arguments, file paths, file contents, tokens, and credentials are **never** transmitted to the ML service.
- **Localhost Only**: The service binds strictly to `127.0.0.1` and does not accept remote network traffic or arbitrary code execution.

---

## 2. Limitations of Synthetic Training Data

> [!WARNING]
> The current model is trained on a synthetic prototype dataset of 36 records.

- **Experimental Prototype**: Holdout accuracy on synthetic data (~63.6%) and medium-risk recall (~25%) do not represent production security guarantees.
- **Uncalibrated Probabilities**: The probability distributions generated by the model are preliminary estimates and are not calibrated against real-world adversarial traffic.
- **Not a Replacement for Deterministic Rules**: The model does not detect all novel prompt injection variants or zero-day bypasses.
- **No Self-Poisoning**: Production audit events and deterministic policy decisions are not automatically ingested as ground truth labels to prevent training data poisoning and drift.

## 3. Quick Start (Windows PowerShell)

All commands below are formatted for Windows PowerShell.

### Step 1: Install Python Dependencies

Ensure Python 3.12+ is installed:
```powershell
python -m pip install -r requirements.txt
# Or install individual packages:
python -m pip install scikit-learn pandas joblib fastapi uvicorn
```

### Step 2: Train the Model

To retrain the Random Forest pipeline with the synthetic training dataset:
```powershell
python ml-policy/train.py
```
This writes:
- Trained pipeline: `ml-policy/models/risk_classifier.joblib`
- Evaluation metrics: `ml-policy/reports/evaluation.json`

### Step 3: Run the Scoring Service

Start the local FastAPI service on `127.0.0.1:8000`:
```powershell
# Option A: Directly using python
python ml-policy/service.py

# Option B: Using uvicorn with explicit app directory
python -m uvicorn service:app --app-dir ml-policy --host 127.0.0.1 --port 8000
```

### Step 4: Verify Service Health (`GET /health`)

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:8000/health" -Method GET | ConvertTo-Json
```
Expected output:
```json
{
  "status": "healthy",
  "mode": "shadow",
  "model": "risk_classifier",
  "version": "0.1.0"
}
```

### Step 5: Test a Manual Prediction (`POST /predict`)

Test predicting a safe read tool:
```powershell
$payload = @{
    tool_name = "read_file"
    tool_category = "filesystem"
    is_mutation = 0
    schema_valid = 1
    path_traversal = 0
    prompt_injection = 0
    suspicious_command = 0
    unknown_tool = 0
    contract_drift = 0
    payload_size = 42
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://127.0.0.1:8000/predict" -Method POST -ContentType "application/json" -Body $payload | ConvertTo-Json
```
Expected response:
```json
{
  "risk": "LOW",
  "confidence": 0.835,
  "class_probabilities": {
    "HIGH": 0.05,
    "LOW": 0.835,
    "MEDIUM": 0.115
  },
  "mode": "shadow"
}
```

## 4. Enabling Shadow Scoring in the TARS Gateway

Shadow scoring is disabled by default to avoid unintended dependencies during standard operation.

### Via Environment Variables
```powershell
$env:ENABLE_ML_SHADOW_SCORING = "true"
$env:ML_SCORING_ENDPOINT = "http://127.0.0.1:8000"
npm run start --workspace=@tars/gateway
```

### Via TypeScript Gateway Configuration
```typescript
import { TarsGateway } from '@tars/gateway';

const gateway = new TarsGateway({
  port: 8443,
  dbPath: './tars.db',
  enableMlShadowScoring: true,
  mlScoringEndpoint: 'http://127.0.0.1:8000',
});

await gateway.initialize();
```

## 6. Features Extracted by the Gateway

The TypeScript gateway extracts 10 structured features before requesting prediction:

| Feature | Type | Description |
|---|---|---|
| `tool_name` | String | Intercepted MCP tool name |
| `tool_category` | String | Inferred category (`filesystem`, `system`, `database`, `search`, `api`, `communication`) |
| `is_mutation` | Integer (0/1) | Whether the tool alters persistent state or executes actions |
| `schema_valid` | Integer (0/1) | Contract input schema conformance |
| `path_traversal` | Integer (0/1) | Path violation or boundary breakout detection |
| `prompt_injection` | Integer (0/1) | Heuristic prompt injection signal |
| `suspicious_command` | Integer (0/1) | Shell execution or terminal command pattern |
| `unknown_tool` | Integer (0/1) | Tool unregistered in contract registry |
| `contract_drift` | Integer (0/1) | Contract schema drift detected |
| `payload_size` | Integer | UTF-8 byte length of argument JSON (without transmitting payload) |
